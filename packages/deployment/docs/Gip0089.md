# GIP-0089: Deployment Guide

Deployment proposal routing 20% of protocol issuance to a new `InnovationAllocation` target controlled by The Graph Foundation, as specified by [GIP-0089](https://github.com/graphprotocol/graph-improvement-proposals/blob/main/gips/0089-innovation-allocation.md). Total issuance is unchanged — `RewardsManager`'s self-mint rate drops from 120.73 to 96.584 GRT/block and `InnovationAllocation` takes the 24.146 difference as an allocator-minted target.

### New contracts (deploy)

| Contract               | Package  | GIP  | Purpose                                                                                                                 |
| ---------------------- | -------- | ---- | ----------------------------------------------------------------------------------------------------------------------- |
| `InnovationAllocation` | issuance | 0089 | Allocator-minted `IssuanceAllocator` target; holds issuance until the Foundation operator withdraws it via `sendTokens` |

### Existing contracts (reused unmodified)

| Contract                          | Package   | Role in this rollout                                                                                                                                                                                                                                           |
| --------------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DirectAllocation_Implementation` | issuance  | Shared implementation `InnovationAllocation` proxies onto — the **same** implementation already used by `DefaultAllocation` and `ReclaimedRewards`. No new Solidity ships with GIP-0089. See [Shared implementation](#shared-implementation-drift-risk) below. |
| `IssuanceAllocator`               | issuance  | Reconfigured via governance TX (`GIP-0089:allocate`) to route 20% of issuance to the new target. Not upgraded — no contract change.                                                                                                                            |
| `RewardsManager`                  | contracts | Self-mint rate reduced from 120.73 to 96.584 GRT/block via `IssuanceAllocator.setTargetAllocation`. Its raw `issuancePerBlock` anchor (120.73) is **never written** by any GIP-0089 script — it is the invariant the config table is validated against.        |

### Shared implementation drift risk

`DirectAllocation_Implementation` is one contract shared by three proxies (`DefaultAllocation`, `ReclaimedRewards`, `InnovationAllocation`). `deploy/allocate/direct/01_impl.ts` runs on the `deploy` action and silently redeploys the implementation if the compiled bytecode differs from the recorded `bytecodeHash` in the address book — which would leave the new `InnovationAllocation` proxy on different code from its siblings.

The mitigation is `packages/deployment/test/bytecode-comparison.test.ts` (`DirectAllocation shared implementation` suite), which asserts the local artifact hash equals the recorded `bytecodeHash` for chains `42161` and `421614`. It runs as part of `pnpm test`. If it fails, that is the signal for a deliberate, recorded decision — upgrade all three proxies together, or pin the implementation — not something to "fix" by updating the expected hash.

## Deployment Process

### How `--tags` drives the deployment

The component tag (`InnovationAllocation`) combined with an action verb (`deploy`, `configure`, `transfer`) selects which lifecycle step runs. The allocation change is a separate goal tag (`GIP-0089:allocate`) because it is a governance TX against `IssuanceAllocator`, not a lifecycle action on `InnovationAllocation` itself.

- `--tags InnovationAllocation,deploy` — deploy the proxy
- `--tags InnovationAllocation,configure` — grant roles
- `--tags InnovationAllocation,transfer` — transfer to governance control
- `--tags GIP-0089:allocate` — generate the allocation-change governance TX batch
- `--tags GIP-0089,all` — verify the full rollout (exits non-zero on any unmet goal). ⚠️ Write-capable: `all` is an action verb, so this run can deploy the proxy, redeploy the shared implementation on artifact drift, and stage governance batches. Safe only post-deployment; for a read-only view use `--tags GIP-0089` or `--tags InnovationAllocation`.
- `--tags GIP-0089` — show status

All scripts are idempotent — they check on-chain state and skip if already done. `sync` runs automatically as a dependency.

### Deployment sequence

```bash
# Deploy, configure, transfer
pnpm hardhat deploy --skip-prompts --tags InnovationAllocation,deploy    --network <network>
pnpm hardhat deploy --skip-prompts --tags InnovationAllocation,configure --network <network>
pnpm hardhat deploy --skip-prompts --tags InnovationAllocation,transfer  --network <network>

# Generate the allocation-change governance TX batch
pnpm hardhat deploy --skip-prompts --tags GIP-0089:allocate --network <network>
# → execute governance TX
pnpm hardhat deploy:execute-governance --network <network>

# Verify
pnpm hardhat deploy --skip-prompts --tags GIP-0089,all --network <network>
pnpm hardhat ia:status --network <network>
```

`--skip-prompts` is required on live networks — without it rocketh prompts for gas-price confirmation before every mutating call.

### Preconditions

Each script checks its own preconditions and skips if not met.

#### Deploy (`InnovationAllocation,deploy`)

| Contract               | Precondition                               | Notes                                                         |
| ---------------------- | ------------------------------------------ | ------------------------------------------------------------- |
| `InnovationAllocation` | `DirectAllocation_Implementation` deployed | Proxy deploys onto the shared implementation; no new bytecode |

#### Configure (`InnovationAllocation,configure`)

| Contract               | Precondition                                                        | Notes                                                                                                                                                                                                         |
| ---------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `InnovationAllocation` | Deployed; `InnovationOperator` present in the issuance address book | Grants `GOVERNOR_ROLE` (governor), `PAUSE_ROLE` (pause guardian), `OPERATOR_ROLE` (`InnovationOperator`) — checked by `checkInnovationAllocationConfigured` ([lib/preconditions.ts](../lib/preconditions.ts)) |

#### Transfer (`InnovationAllocation,transfer`)

| Contract               | Precondition | Notes                                                                           |
| ---------------------- | ------------ | ------------------------------------------------------------------------------- |
| `InnovationAllocation` | Configured   | Revokes deployer `GOVERNOR_ROLE`, transfers ProxyAdmin to the protocol governor |

#### Allocate (`GIP-0089:allocate`)

| Precondition                                                                                       | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GIP-0088 `issuance-connect` complete                                                               | `RewardsManager` wired as an `IssuanceAllocator` target holding the full issuance as a self-minting allocation. Checked via `checkIssuanceConnectComplete` ([lib/contract-checks.ts](../lib/contract-checks.ts)); a revert (RM not yet on the `IIssuanceTarget` implementation) is treated as incomplete, not an uncaught error. Without this, RM's entry in the allocation table is also an increase from zero, `InnovationAllocation` sorts first instead of second, and the RM call reverts mid-batch — the script refuses to generate a batch and returns instead.                                                                                         |
| `InnovationAllocation` deployed                                                                    | The batch targets its address. Enforced: a target configured at a nonzero rate but not deployed makes the helper refuse and return without emitting anything, rather than skip the row. The table has already been validated against `RewardsManager`'s issuance rate, so a partial batch would free issuance the missing target cannot claim and divert it to the `IssuanceAllocator` default target. Not bypassable by `GIP_0088_ASSUME_UPGRADED` — an undeployed target has no address, so its call is unencodable at any point in the sequence. A target configured at 0 (`RecurringAgreementManager` on Sepolia) contributes nothing and stays skippable. |
| Config `IssuanceAllocator.allocations` total equals `RewardsManager`'s on-chain `issuancePerBlock` | Validated by `validateIssuanceAllocations` before any TX is emitted — errors on mismatch                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| —                                                                                                  | Ordering is load-bearing: the shared helper (`applyIssuanceAllocationTable`, [lib/issuance-allocate.ts](../lib/issuance-allocate.ts)) sorts pending changes decrease-first, so `setTargetAllocation(RewardsManager, …)` is always emitted before `setTargetAllocation(InnovationAllocation, …)` — the allocator's default target absorbs slack and cannot go negative, so the reverse order reverts `InsufficientAllocationAvailable`.                                                                                                                                                                                                                         |

## Environments

The same commands apply to all environments. What differs is how the `GIP-0089:allocate` governance TX is executed.

| Environment       | Governance execution                              | Speed    |
| ----------------- | ------------------------------------------------- | -------- |
| Fork (localhost)  | `deploy:execute-governance` impersonates governor | Instant  |
| Testnet (Sepolia) | `deploy:execute-governance` signs with EOA key    | ~minutes |
| Mainnet (Arb One) | TX batch uploaded to Safe for council multisig    | ~days    |
