# T5d test mapping: RewardsManager eligibility oracle and reclaim

New tests are in `packages/issuance`, on T5a's `RewardsManagerSharedTest` (the RewardsManager Hardhat artifact behind a GraphProxy). `RMEligibilityOracleMock` (the fixture's `oracle`, deployed eligible by default) replaces `MockRewardsEligibilityOracle`: where the old test deployed it with `false`, the port calls `setDefaultResponse(false)` through the shared `_useEligibilityOracle`. `RMIssuerMock` (`issuer`) plays the legacy Staking contract and the old `MockSubgraphService`, so `closeAllocation` becomes `_close` (`takeRewards`) and `callReclaimRewards` becomes `issuer.reclaim`. `setupIndexerAllocation` becomes the shared `_signalThenAllocate` (signal, `vm.roll(+1)`, allocate, as the separate Hardhat transactions), and `mineEpoch` / `mine(n)` become `vm.roll(EPOCH_LENGTH)` / `vm.roll(5)`. The hand-counted 1400 / 1600 GRT values (`expectApproxEq`, 20000 wei) are replaced by exact values derived from the rolls with the shared formula helpers. Where a pre-denial allocation was closed in the Hardhat transaction after `setDenied`, the port rolls one block too, so the subgraph-level reclaim of that block stays in play. No ported case uses a zero-token allocation (the carried `RMIssuerMock` hook caveat does not apply).
