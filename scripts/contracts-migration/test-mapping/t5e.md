# T5e test mapping: RewardsManager signal/allocation update accounting and snapshot inversion

New tests are in `packages/issuance`, on T5a's `RewardsManagerSharedTest` (the RewardsManager Hardhat artifact behind a GraphProxy). `setupSubgraphWithAllocation` becomes the shared `_signalThenAllocate` (`SIGNAL` / `ALLOCATION` instead of the old 1000 / 10,000 GRT; signal, `vm.roll(+1)`, allocate), and `issuer` plays the legacy Staking contract. The hooks are called directly (the old tests called them as governor; they have no access check). `mine(n)` becomes `vm.roll(n)`. Hardhat batched blocks (`evm_setAutomine(false)` … `evm_mine`) become consecutive calls with no `vm.roll` in between. Where a following Hardhat transaction mattered (a sync, or `setDenied` after the allocation), the port rolls one block. Expected values come from the rolls through the shared `_subgraphRewards` and `_expectedRewardsPerAllocatedToken`, and are asserted exactly next to the old `gt` / `lt` checks. `hardhat_setStorageAt` becomes `vm.store` at `keccak256(abi.encode(sd, uint256(16))) + field`, and `test_SnapshotInversion_StorageSlotsMatchLayout` checks that layout. No ported case uses a zero-token allocation, so the `RMIssuerMock` hook caveat does not apply.

## Coverage

`contracts/rewards/RewardsManager.sol`: every external/public name in `functionsHit` is called by an issuance test. No `MISSING` names. This PR adds direct calls to `onSubgraphSignalUpdate`, `onSubgraphAllocationUpdate`, `getAccRewardsForSubgraph`, `getAccRewardsPerAllocatedToken` and `getRewards`, and reaches `_updateSubgraphRewards` with an inverted snapshot (A < S).
